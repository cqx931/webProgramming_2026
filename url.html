URL Basics

What is a URL?

A URL (Uniform Resource Locator) is the address you type into your browser to access a web page or resource. URLs tell the browser where to find files like HTML pages, images, stylesheets, and scripts.

When building websites, you need to link to other pages and resources. Understanding the three types of URLs—absolute, relative, and root-relative—is crucial for building maintainable websites.

Why Does This Matter?

  • Different URL types work differently depending on file location
  • Broken links occur when URLs don't point to the correct location
  • Server configuration affects how URLs resolve
  • Moving files can break relative URLs if you're not careful

1. Absolute URLs

An absolute URL includes the complete address from the root of the web, including the protocol (http/https) and domain name. It always points to the same location, regardless of where the current page is.

Format:

protocol://domain.com/path/to/page.html

Examples:

The class website in absolute url: https://cqx931.github.io/webProgramming/

When to Use Absolute URLs:

  • Linking to external websites
  • When you need a URL that works from any location
  • In navigation menus that need to work on all pages

2. Relative URLs

A relative URL describes a path relative to the current file's location. It does not include the protocol or domain. The browser figures out the complete URL based on where the current page is.

Format:

path/to/page.html

Common Relative URL Patterns:

Pattern Meaning Example
index.html File in the same folder Links to index.html in same directory
./index.html Current folder (. = current) Same as above, more explicit
../index.html One folder up (.. = parent) Links to parent directory
../images/devices.jpg Sibling folder Go one folder up, then into images folder to find devices.jpg in

When to Use Relative URLs:

  • Linking between pages on your own website
  • When you want flexibility to move your site to different domains
  • Linking to local images, stylesheets, and scripts
Important: Relative URLs can break if you move files around. Always check links after reorganizing your file structure!

3. Root-Relative URLs

A root-relative URL (also called "absolute path" in some contexts) starts with a forward slash /, which represents the root of the website. The browser adds the protocol and domain automatically. These work from any page on your site.

Format:

/path/to/page.html

How It Works:

If you're on https://example.com/pages/contact.html and use the URL /about.html, the browser will resolve it as https://example.com/about.html (not in the /pages folder).

Root-Relative URL Examples:

URL Resolves To (on example.com)
/index.html https://example.com/index.html
/about.html https://example.com/about.html
/pages/contact.html https://example.com/pages/contact.html
/images/logo.png https://example.com/images/logo.png

When to Use Root-Relative URLs:

  • Main navigation links that should work from every page
  • When you want the simplicity of absolute URLs but site flexibility
  • For site-wide resources like stylesheets and scripts in the root
  • Large sites where relative paths would be complex

GitHub Pages

If your GitHub pages are hosted from a normal repository (not the one dedicated to your user GitHub Pages), your root is not the root of your current repository, but to the general user: Current Root
Important: Root-relative URLs only work for websites served from a web server. If you open an HTML file directly in your browser (file:// protocol), root-relative URLs won't work.
